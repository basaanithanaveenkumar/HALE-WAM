TL;DR. HALE-WAM is a 176M-parameter causal transformer that jointly generates a text response, a 16-step continuous action chunk, and predicted future RGB frames — all from a single forward pass over camera frames, robot state, and a language instruction.
  • Problem: Existing VLA policies have no world model; existing video world models have no policy. Combining them usually means two separate models.
  • Key idea: Read three types of hidden states from one causal MoE decoder via special tokens: <halo_action> → flow-matching head, <halo_world_video> → DiT world model.
  • Architecture: ViT (6L) + 8-layer DeepSeekMoE decoder + velocity MLP action head + 8-block Diffusion Transformer for future frames.
  • Training: Joint CE + flow-matching MSE + visual CFM + VGG perceptual + SSIM + temporal smoothness losses on a single GPU.
  • Status: Qualitative results at step 24,000. Quantitative benchmarks (action error, PSNR/SSIM vs horizon) in progress.
176M params · 3 output heads · 1 forward pass

Problem Statement

Robot learning has two mostly separate threads: policies that map observations to actions, and world models that predict future observations. Keeping them separate has three practical costs:

1. No self-verification. A policy that cannot predict the visual outcome of its actions cannot reason about whether its plan makes sense before committing to it.
2. Wasted video data. Hours of robot video without action labels (pre-collected footage, third-person demonstrations) cannot be used to train a policy, but can train a world model.
3. Compounding inference costs. Running a policy and a separate world model in deployment doubles latency and memory.

HALE-WAM addresses all three by reading action and world-model outputs from the same hidden states that produce language — no separate forward passes, no separate training objectives that need careful balancing between independent networks.

Why is joint training hard? The action head needs fine-grained temporal dynamics; the world model needs high-frequency spatial detail; and the language head needs semantic abstraction. Fusing all three in one sequence model risks mutual interference in the shared representation.

Method

  1. Data pipeline

    Training episodes come from AiroaMoMa (wheeled robot manipulation) and EO-Data1.5M (general egocentric video). Each episode provides N context frames, proprioceptive state vectors, a language annotation, a ground-truth action chunk, and N_future future frames. The dataloader samples random windows, applies colour jitter and random crop, then packs everything into a ChatML-formatted token sequence with special markers: <image>, <state>, <halo_action>, <halo_world_video>.

    Three training phases are supported: VLA pretraining (OpenX, Bridge, DROID + synthetic SynGrasp-1B), embodied VLM mid-training (RefSpatial, RoboPoint, Robo2VLM — no action labels needed), and preference post-training (FlowPRO rollback pairs, APO interventions, DAgger corrections).

  2. Model design

    Vision encoder. Six dense transformer layers process each frame independently. Patch size 16 gives 14×14 = 196 tokens per frame. An MLP projector maps 512-d patch embeddings into the decoder's embedding space.

    Causal MoE decoder. Eight layers of multi-head attention (8 heads, dim 512) with causal masking, followed by DeepSeekMoE FFN: 6 routed experts + 2 shared experts, top-2 routing, expert hidden dim 2048. Gradient checkpointing is on by default. Vocabulary embeddings use ALBERT-style factorisation (512 → 128) to reduce the embedding table from ~25M to ~2M parameters.

    ★ Key innovation: Special tokens <halo_action> and <halo_world_video> are inserted into the input sequence. Their final hidden states are routed to their respective heads — no architectural modification to the causal decoder is needed.

  3. Flow-matching action head

    A 4-layer MLP with 1024 hidden units implements the velocity field $v_\theta(x_t, t, h_\text{act})$ where $x_t = (1-t)x_0 + tx_1$ is the interpolated action chunk, $t \sim U(0,1)$, and $h_\text{act}$ is the decoder hidden state at <halo_action>.

    Training loss: $\mathcal{L}_\text{act} = \mathbb{E}_{t,x_0,x_1}\bigl[\|v_\theta(x_t, t, h) - (x_1 - x_0)\|^2\bigr]$

    Inference: 24-step Euler ODE integration $x \leftarrow x + v_\theta(x, t, h) \cdot \Delta t$, starting from $x_0 \sim \mathcal{N}(0, I)$.

  4. DiT world model

    Each future frame $i$ receives a unique conditioning vector $c_i$ built from four components: (1) cross-attention of $h_{\text{wv},i}$ over visual context, (2) sinusoidal frame-index embedding $\sin(f+i)$, (3) pixel encoding of the last observed frame (scene anchor), (4) gated fusion with the diffusion timestep $t$ via $\tilde{c} = \sigma(W_g c_i) \odot \text{emb}(t) + W_c c_i$.

    $\tilde{c}$ modulates all 8 DiT blocks through adaLN-Zero. Classifier-free guidance uses a learned null context, dropped in during training with $p=0.1$. Inference uses a second-order Heun ODE solver.

    ★ Anti-blur losses: Three auxiliary losses operate on the analytic clean-frame estimate $\hat{x}_1 = x_t + (1-t)v_\theta$: VGG perceptual (weight 0.1), SSIM (weight 0.4), and temporal smoothness between consecutive $\hat{x}_1$ estimates (weight 0.2). These come for free from the straight-line flow formula — no extra forward passes.

  5. Training procedure

    Joint optimisation with AdamW ($\beta_1{=}0.9, \beta_2{=}0.95$), AMP (bfloat16), and gradient accumulation. Loss weights: $\mathcal{L} = \mathcal{L}_\text{CE} + \mathcal{L}_\text{act} + 8 \cdot \mathcal{L}_\text{vis}$. The visual loss weight 8 compensates for the smaller gradient magnitude of the visual CFM term relative to CE. Gradient norm is clipped to 1.0. Checkpoints save full training state (model, optimiser, AMP scaler) for exact resume.

Demo & Quick Start

Run HALE-WAM locally in three commands:

  1. git clone https://github.com/basaanithanaveenkumar/HALE-WAM && cd HALE-WAM
uv venv && source .venv/bin/activate && uv pip install -e .
  2. python scripts/train.py --dataset moma --moma_data_root /path/to/moma \
  --moma_num_frames 5 --num_predict_frames 5 \
  --batch_size 1 --grad_accum_steps 8 --vis_every 500
  3. # Run standalone inference with a saved checkpoint
python scripts/visualize.py --checkpoint checkpoints/run1/model_best.pt \
  --moma_data_root /path/to/moma --output_dir vis_out --diffusion_steps 50

Inference API:

logits, action_h, vis_ctx, wv_h = model(images, input_ids, attention_mask, states)
actions = model.sample_actions(action_h)              # [B, n_act, 16, action_dim]
frames  = model.predict_visual_future(                # {"rgb": [B, F, 3, H, W]}
    images, vis_ctx, num_frames=5, world_video_query_hiddens=wv_h)

Limitations & Ethical Considerations

Known

Patch artefacts in world model

At step 24k, imagined frames show 16×16 block artefacts from the patch tokenisation. Expected to improve with longer training and higher visual loss weight.

Pending

No quantitative benchmarks yet

Action error, PSNR, SSIM, and LPIPS evaluations against held-out episodes have not been run. Reported results are qualitative only.

Known

Single-robot domain

Trained on AiroaMoMa (wheeled mobile manipulator) and EO egocentric data. Generalisation to other robot morphologies, camera configurations, or action spaces is untested.

Open

Safety in deployment

The world model head could in principle generate photorealistic frames of scenes that did not occur. Downstream use of imagined frames for planning requires careful verification.

Compute

Training cost

Full training requires an A100-class GPU. The 176M parameter count is compact by modern standards, but joint CE + visual loss training is slower per step than policy-only training.

Open

Temporal credit assignment

The flow-matching head sees only the hidden state at one token position. Multi-step planning and credit assignment over long horizons are open research questions.
